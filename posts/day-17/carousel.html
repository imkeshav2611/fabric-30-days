The simple version

A conveyor belt with sorting stations.

Parcels drop onto a belt from many loading doors. Along the way they are scanned, sorted and sent down the right chute.

An eventstream is that belt: events in, shaped in motion, delivered where they are needed.

For engineers

What engineers should know

It speaks KafkaAn eventstream exposes a Kafka-compatible endpoint, so existing producers can send to it with little change.
Database changes are a sourceChange data capture from SQL Server, PostgreSQL, MySQL, Cosmos DB and others can flow in as events.
Delivery is at-least-onceAn event can arrive twice. Downstream logic should tolerate duplicates.
Windows are how you aggregateGroup by time windows to turn an endless stream into counts and averages.
The honest part

Eventstream or a pipeline?

Eventstream

  • Data arrives continuously
  • You need it within seconds
  • Several consumers need the same events

Pipeline

  • Files arrive on a schedule
  • Hourly or daily freshness is fine
  • The source can only be queried in bulk

The catch: filtering late is expensive. Every event you carry to the destination costs storage and compute. Drop what you do not need as early as possible.
