Microsoft Fabric, Day 7 of 30: shortcuts.

A surprising share of data engineering is copying data from one place to another and then keeping the copy fresh.

Shortcuts remove a lot of that. A shortcut is a pointer inside OneLake to data that lives somewhere else: another lakehouse, Azure Data Lake Storage, Amazon S3, Google Cloud Storage and more. It looks like a normal folder. Nothing is copied, and if the target is a Delta table it behaves like any other table.

The details matter more than the idea. A shortcut to another OneLake location checks the identity of the person querying. A shortcut to external storage uses the credentials saved in the connection. Removing a shortcut never deletes the data behind it, but deleting a file inside a shortcut does delete it at the source. And performance is the source's performance, including egress cost when it sits in another cloud.

My rule of thumb: use a shortcut when the data is already in a good format and somebody else owns it. Copy when the source is slow, unstable or needs heavy reshaping anyway.

No project story today. Only this: a shortcut removes the copy, not the dependency.
