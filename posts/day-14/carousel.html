The simple version

A courier who works from the inside.

The office does not let strangers walk in. Instead, an employee carries parcels out to the delivery van when asked.

The gateway is that employee: software inside your network that fetches data on request.

How it works

How a request travels

1A pipeline or report in Fabric asks for on-premises data
2The request waits in a secure cloud relay
3The gateway calls out, picks it up and queries the source
4Results travel back through the same outbound connection
Why security teams accept itThe gateway only makes outbound connections. Nothing on the internet can dial in.
For engineers

Running it properly

Use standard modeStandard mode serves many users and sources. Personal mode works only with Power BI and cannot be shared.
Build a clusterTwo or more gateway machines in a cluster avoid a single point of failure.
Keep it updatedA new version ships every month, and only the last six releases are supported.
Put it near the dataThe gateway machine does real work. Place it close to the source and size it for the load.
The honest part

Gateway or something else?

On-premises gateway

  • Sources on servers in your own network
  • Strict rules against inbound access
  • A mix of cloud and on-premises data

Consider instead

  • Sources in an Azure virtual network
  • Data already replicated to the cloud
  • A source that can push files out

The catch: the gateway is a server someone must own. Most "the pipeline failed" tickets on hybrid projects trace back to a gateway that was offline, full or out of date.
