The simple version

One report card per student.

A school prints one results system, not one per child. Each student opens it and sees only their own marks.

How it works

Where you can define it

1OneLake security: on the table, enforced across engines
2Warehouse and SQL endpoint: a T-SQL security policy
3Semantic model: roles with a DAX filter
4Pick one place as the source of truth
The closer to the data, the betterA rule on the table protects every tool. A rule in one report protects only that report.
For engineers

The gaps you must know

SQL rules do not cover SparkA security policy on the SQL endpoint does not protect direct access to the Delta files through a notebook.
Model rules apply to Viewers onlyAdmin, Member and Contributor roles on the workspace are not restricted by semantic model security.
Direct Lake behaves differentlyWith SQL rules, Direct Lake on SQL falls back to DirectQuery. Direct Lake on OneLake does not apply them at all.
Test as the userAlways check with a real restricted account. "It works for me" means nothing if you are an Admin.
The honest part

Where should the rule live?

On the data

  • Several tools read the same table
  • Engineers and analysts both query it
  • The rule is a compliance requirement

In the model

  • Only Power BI consumes the data
  • Rules depend on business hierarchies
  • Report authors own the logic

The catch: security defined in two places will disagree. When it does, people see either too much or too little, and both end in an incident.
