The simple version

Fewer, better-packed trucks.

A delivery firm does not get faster by buying more trucks if they leave half empty and drive across town for one parcel.

Fast Spark is the same: move less data, fewer times, in sensible loads.

How it works

The fixes, in order of payoff

1Filter and select early, so less data flows through
2Broadcast small tables in joins to avoid a shuffle
3Fix skew: one giant key can stall a whole job
4Cache only what you reuse more than once
5Compact files and choose a sensible layout
Read the plan firstThe Spark UI shows which stage takes the time. Tune that stage, not the whole job.

The honest part

Tune the code or add compute?

Tune first

  • One stage dominates the run time
  • A join or shuffle is the bottleneck
  • Thousands of small files are being read

Add compute

  • The plan is clean and data simply grew
  • The job is already well partitioned
  • The deadline is fixed and close

The catch: caching everything feels safe and makes jobs slower. Cached data takes memory away from the work. Cache what you reuse, and release it after.
