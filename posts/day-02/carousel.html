The simple version

OneLake is OneDrive for data.

Your company has one OneDrive, not one per team. Everyone works in it, and permissions decide who sees what.

OneLake is the same idea for analytics data. One lake per organisation, already there on day one.

For engineers

What matters under the hood

It speaks ADLS Gen2OneLake supports the ADLS Gen2 APIs and SDKs, so tools built for Data Lake Storage keep working.
Region follows capacityA workspace's data lives in the region of the capacity it is assigned to.
Storage is billed on its ownStored gigabytes are charged separately from the compute capacity.
Open table formatsFabric engines write Delta Parquet. OneLake can also present tables as Iceberg for other engines.
The honest part

Does one lake mean no silos?

It helps when

  • Teams need the same data without copying it
  • Data is spread across Azure, AWS and Google
  • You want one place to govern access

It will not fix

  • Unclear ownership of each dataset
  • A messy workspace structure
  • Poor data quality at the source

The catch: one lake can still become one swamp. Decide workspace boundaries and who owns each table before teams start loading data.

From real work

OneLake on a real project

A people-analytics platform where employee data was split across many files.

1Performance, ratings and learning data landed in one Lakehouse
2Semantic models read from that single copy
3Role-based access and row-level security protected it
4Daily pipelines kept it fresh

The value was not the storage. It was one agreed copy.
